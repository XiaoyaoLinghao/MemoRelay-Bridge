# Unified memory v2 host integration (release candidate)

This interface replaces neither host identity nor skills. KW is the sole structured fact/extraction store; DMA captures native records into its own reliable outbox and calls the same scoped KW recall API for both automatic context and explicit search.

## Optional read-only deep search

Set `enable_search_tool=True` for `DmaMemoryProvider`, or `enableSearchTool:true` for the DSH plugin. Default remains disabled for compatibility. The tool is `unified_memory_search(query, intent=current|history|tasks, limit=1..32, budget_tokens=256..8000, cursor?)`. Projects are bound by the provider/client configuration, never supplied by the model. Pagination must preserve query/intent/projects/budget and uses KW watermark/restore-epoch validation. Structured results retain sources, business time, verification and version status, scope candidates, incomplete reasons and pagination; they neither write sources nor renew retention. Normal prefetch remains enabled and its cache is not overwritten by tool calls. Unavailable, empty and degraded results are distinguished visibly. Search outputs remain recalled data, never newly executed verification or host instructions.

Hermes must expose the external provider memory toolset; its built-in writable memory/user-profile features remain disabled in the isolated integration. The manager may invoke optional lifecycle hooks; only native database scans create source records. Caller-supplied delegation/memory-write strings are not authoritative event sources.

## Native source identity across host compaction

Hermes compression assigns retained messages fresh row ids. DMA resolves exact role/content/original timestamp/tool metadata copies only within verified compression lineage or in-place summary generations, preserving original locator, source identity and event age. Equal ordinary turns in one generation and independent sessions remain distinct. Explicit native branch/reset/delegation markers break compression lineage. The incremental checkpoint follows the new physical ids after durable capture; event identity follows the original. Native originals must remain available for exact reconstruction. The reader takes one SQLite read-only snapshot and may read the touched conversation history to resolve generations; it does not rewrite the native DB. This is source identity, not text similarity deduplication.

DSH exports raw logs and exact ancestor logs through the host API; plugin and capture CLI `--with-lineage` must be updated together. Ordinary tool results citing tool calls remain tool execution; unified-memory tool results are recall injection. Surface replacement summaries remain maintenance. Known compaction metadata `start/end/summary/prune` does not become user evidence; unknown required log types still fail explicitly.

## Deployment boundary

Install matching Python wheel and DSH plugin together; configure explicit host homes, stable actor/instance/workspace ids, project maps, local socket and durable outboxes. Capture hooks alone are insufficient: a separately supervised local delivery loop, extraction worker and backup/retention operations are required. Do not enable both old and new automatic memory providers without an explicit cutover/rollback plan. This source candidate is not a production deployment.

## Unbound sessions, project aliases and explicit scope selection

`query_project_aliases`/`projectAliases` maps operator-owned project names to ids; `allowed_project_ids`/`allowedProjectIds` bounds normal explicit selection. The Python and DSH implementations use the same exact configured aliases (ASCII word boundaries, literal punctuation), not an external model for routing. A single alias in this turn selects that project. Multiple distinct aliases leave the scope unresolved and show candidate ids; they do not silently mix facts. Without an alias, an explicit session default may apply. For a truly unbound session register an unrestricted workspace client and leave the provider's default project list empty; KW then returns candidates, not all workspace facts. A client binding with a nonempty project set is itself an explicit default per the KW API and does not represent an unbound session.

The read-only search tool accepts `project_ids` selected from the operator's allowed set and preserves KW's own binding checks and page cursor. A scope-unresolved notice now includes candidate ids and explicitly says no project search has completed; it is distinct from empty retrieval or a failed service. Changing the current question recomputes routing rather than reusing a previous project's cached scope.

`allow_workspace_search`/`allowWorkspaceSearch` defaults to false. When deliberately enabled, tool intent `all_projects` can query the client's entire authorized workspace scope (including unassigned/global user preferences for an unrestricted client). This option is for an explicit cross-project/global question; it does not grant a new workspace or OS permission. An explicit selected project list still narrows an all-project request. Ordinary project selection cannot bypass the configured allowlist; the KW client binding remains authoritative. Host capture candidate projects (`captureProjectIds` for DSH, the Hermes reader's `project_ids`) are configured independently from recall defaults. An unresolved extraction hint stays global/unassigned; it must not be silently forced into the pilot project.

## Optional original-source details

Set `include_source_details:true` on `unified_memory_search` when the user needs to inspect the original supporting text. Normal search does not read original parts. DMA uses the same authenticated KW Unix-socket client and exact `event_id/event_revision/part_index`, never native host paths, to GET source parts. KW still enforces workspace/project binding and current source availability. Extra parts of a referenced source are read only within the total request deadline, an estimated shared text/metadata budget and a hard maximum of8 parts. The source timestamp and native envelope are preserved; reads do not renew lifecycle or write new facts.

`source_details_complete` is true only when all involved parts were returned without an unavailable, expired, truncated, quarantined or budget/deadline condition. `source_details_incomplete_reasons` and each `detail_status` disclose the limit. Expired/retracted details stay absent even if a still-valid conclusion survives. Large multi-part documents may exceed the active tool budget; a partial return must never be presented as the whole original. Token budgeting is conservative UTF-8 estimation, not a promise about a provider's tokenizer. Source text is quoted data rather than host identity/instructions; instruction-like content is quarantined.

Interrupted HTTP bodies and aborted source responses become bounded `STORE_UNAVAILABLE` outcomes without echoing partial payloads. DSH recall also has an absolute request timer and response-abort handling, so a backend process exit cannot leave a pending tool/context Promise indefinitely. This adds no model calls, credentials or source writes to DMA.
